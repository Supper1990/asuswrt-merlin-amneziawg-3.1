# Router Geo routing — development branch

This change is not a release and has not been validated on Asuswrt-Merlin.
It does not address or diagnose the reported ARMv7 hang. Memory policy and
the existing tunnel watchdog restart policy are unchanged.

## Behavior

- New `awg_router_geo` setting, enabled only by the exact value `1`. Missing
  settings retain previous behavior. Save the checkbox with Apply.
- IPv4 traffic generated by the router is matched against the existing
  `awg_dst` set (selected GeoIP, GeoSite and custom lists), independently of
  the default LAN policy. No all-traffic router mode is introduced.
- `AWG_OUTPUT` is attached before the existing AntiFilter OUTPUT hook. It
  assigns mark `0x100`, using existing table 300 and masquerading.
- Already marked traffic, local destinations, LAN, loopback, link-local,
  multicast, limited broadcast, DHCP/NTP, and the current IPv4 peer endpoint
  are excluded. The live AmneziaWG UDP source port is excluded even if the
  endpoint changes. Activation fails if the live port cannot be read.
- AntiFilter retains its existing independent behavior, including OUTPUT.
  A RETURN from the Geo chain does not bypass other addons or AntiFilter.
- GeoSite uses addresses in `awg_dst` populated through dnsmasq and existing
  pre-resolution. This does not intercept applications' independent DoH DNS.

## Lifecycle and recovery

Apply/start/firewall replay build the chain. Cleanup removes its OUTPUT
hooks before deleting `awg_dst`. Turning off the setting removes only this
new chain, preserving AntiFilter.

The existing firewall watchdog checks enabled/disabled state, duplicate or
misordered hooks, the live transport port exclusion, and marking. Existing
managed-rule snapshots include the new chain and hooks, so the full health
check detects missing/extra/modified exclusion rules. Repairs use the
existing firewall repair path. A healthy tunnel need not be restarted just
because its router Geo rules are missing.

Apply rollback restores the previous Geo OUTPUT chain and hook positions
without replaying other addons' or AntiFilter rules.

## Verification boundary

Local shell syntax and simulated-command tests cover default-off behavior,
transport validation, failed rule insertion, hook health, watchdog repair,
and scoped rollback. They cannot establish actual rerouting, NAT, BusyBox
compatibility, DNS interaction with Diversion, or memory behavior on Merlin.

Before release, on an explicitly selected test router with recovery access:

1. Record OUTPUT rules, policy routing, installed version and settings.
2. With the setting absent/off, verify existing LAN and AntiFilter behavior.
3. Enable with a known Geo destination outside MYAWG; verify counters and
   an actual router-originated connection. Verify direct destinations and
   tunnel transport stay direct, including after endpoint/port changes.
4. Verify GeoSite via dnsmasq alongside Diversion and verify LAN policies.
5. Remove a test chain rule/hook, then run watchdog; confirm restoration
   without a daemon restart. Repeat with a duplicate/misordered hook.
6. Verify Apply, firewall restart, stop/start, disabling, and reboot.
7. Inject an Apply failure and verify rollback restores the previous OUTPUT
   rules while preserving AntiFilter and other addons.

Do not perform these mutation tests on the working RT-AX88U Pro without
separate authorization. No router configuration is changed by this branch.
