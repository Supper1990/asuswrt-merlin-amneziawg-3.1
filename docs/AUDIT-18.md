# Исправления аудита: 2.2.0-18

База патча: опубликованная 2.2.0-17, commit `d3348acc54161df4f5f4b795037c7ea6e4aac57b`.
Патч меняет аддон и сборочные скрипты; исходные версии ядра AmneziaWG не меняет.

## Что изменено и как проверять

| Аудит | Изменение | Проверка / граница |
|---|---|---|
| A01 | GeoIP целиком проверяется и нормализуется до замены файла. HTML и неверные IPv4/CIDR отклоняются. | `test_bad_download_keeps_geoip_cache`, `test_cidr_validation_keeps_existing_output`. |
| A02 | Перед очисткой проверяются выбранные списки; сохраняются runtime и DNS; ошибка применения запускает восстановление только правил аддона. Восстановление основной таблицы выполняется до проверки её здоровья. | `test_firewall_failure_restores_old_set_and_dns`, `test_scoped_rollback_excludes_other_addons`. Это откат при обнаруженной ошибке, а не атомарная транзакция между ядром, DNS, файлами и настройками Merlin. Обрыв питания и ошибки самого отката не покрываются гарантией. |
| A03 | Поддерживается выбор категории с `@attribute`; неподдерживаемые keyword/regexp и расширение full явно отражаются в предупреждениях. | `test_geosite_attribute_syntax`. Полная семантика GeoSite НЕ реализована: full в dnsmasq охватывает поддомены, keyword/regexp пропускаются. Категории со ссылкой на неизвестное имя отклоняются. |
| A04 | Поле DNS формирует `server=/domain/IPv4` для выбранных доменов. Пустое поле оставляет DNS роутера. | Код `setup_firewall_body`; конфигурация проходит `dnsmasq --test` на роутере. Поле не настраивает DNS всех устройств и не обещает отправку самих DNS-запросов через туннель. |
| A05 | AntiFilter сравнивает полный нормализованный состав кеша и ipset, а не нижний порог числа записей. Основной ipset отдельно проверяет наличие статических записей. | `test_partial_aux_loss_above_old_floor_is_restored`, `test_static_loss_cannot_be_hidden_by_dynamic_entries`. Нормальное истечение динамических DNS-записей допустимо. |
| A06 | Ошибки создания маршрута/правил возвращают ошибку. Содержимое MYAWG_CHAIN заменяется через одну операцию iptables-restore; неизменная цепочка не пересоздаётся. | `test_aux_route_failure_is_failure`, `test_aux_rule_failure_is_sticky`; реальная семантика iptables-restore на Merlin требует проверки после установки. |
| A07 | Позиция AWG заново читается после удаления старого перехода MYAWG. | `test_attach_recounts_awg_index_after_removal`. |
| A08 | Новый набор сначала загружается во временный ipset. Ошибка загрузки/swap сохраняет прежний кеш; ошибка записи кеша вызывает обратный swap. Повреждённый кеш сбрасывает условные HTTP-заголовки. Hash сверяется с содержимым кеша. | `test_failed_staging_and_swap_preserve_cache`; общий crash-safe commit кеша, метаданных и ядра при обрыве питания не гарантируется. Следующий repair сверяет состав заново. |
| A09 | Фоновый процесс обновляет JSON. UI различает интерфейс, недавний handshake и устаревший статус. Для AntiFilter разделены включение в настройках и наличие runtime. | `update_status`, `status_loop`, `updateStatusUI`; recent handshake не равен проверке открытия конкретного сайта. |
| A10 | Для каждой операции записывается отдельная квитанция running/succeeded/failed с ID. UI ждёт её, а не истечения 15/60 секунд или остановки процесса. Update Geo сохраняет текущие поля. | `test_operation_receipts_are_independent`, `test_browser_validation_mac_and_operation_completion`. Тайм-аут означает отсутствие подтверждения, а не успех. |
| A11 | MAC сохраняется при редактировании. Проверяются адреса устройств, дубли и политики. | Браузерный тест и `validate_runtime_settings`; сохранённый MAC используется, но отдельный редактор MAC не добавлялся. |
| A12 | JSON экранируется общей функцией; счётчики показывают записи ipset и уникальные домены DNS-конфигурации. | `test_json_backslash_and_controls`. Число записей ipset включает сети и динамические адреса; это не число всех IPv4 внутри подсетей. |
| A13 | Удалена очистка общей таблицы conntrack. | `test_no_global_conntrack_flush`. Уже открытые соединения могут потребовать переподключения после изменения политики. |
| A14 | DNS-worker имеет PID, ограничение времени запроса и очередь нового заполнения. Перед Apply/Stop предыдущий worker останавливается. | `prefill_worker`, `cancel_prefill`; задержка остановки зависшего запроса ограничена ожиданием, при неудаче Apply возвращает ошибку. |
| A15 | Оба пути загрузки используют одну настройку автозапуска. В UI добавлен флажок; по умолчанию включён, явный 0 отключает загрузку. Ручной Start остаётся отдельным действием. | Проверка содержимого пакета: S99 вызывает boot_start. На роутере проверить перезагрузкой с каждым положением флажка. |
| A16 | Обновление берёт отдельную блокировку, дожидается текущих изменений, скачивает и проверяет новый и прежний пакеты до Stop. Ошибка установки вызывает попытку вернуть прежний пакет. Force-architecture fallback удалён. | `test_update_validates_rollback_before_stopping`, `test_update_failure_reinstalls_previous_package`. Если прежний релиз удалён, обновление отменяется; при ошибке отката recovery-файлы сохраняются в /opt. Ручной запуск opkg вне аддона не участвует в этой блокировке. |
| A17 | В UI указаны границы IPv4/DNS; IPv6 endpoint отклоняется. Подсети входящих клиентов AntiFilter настраиваются; NAT остаётся по меткам, без привязки только к tun21. | Полная маршрутизация IPv6 НЕ добавлена. Клиенты OpenVPN/IPsec должны использовать DNS роутера. DNS-перехват по-прежнему относится к br0, DoH полностью не контролируется. |
| A18 | Сборка пакета и серверная публикация запускают регрессионные тесты; обязательные ошибки сборки больше не игнорируются. Пишется build-manifest.txt. | Проверка тестовой упаковки. Полная побитовая воспроизводимость НЕ обеспечена: базовые Docker-образы и apt не закреплены снапшотами. Полноценная сборка ARM64 выполняется на VPS. |

## Результат локальной проверки

- `bash tests/run.sh`: **30 тестовых методов, OK**. Источник числа — итог Python unittest; внутри методов есть дополнительные subtests. Это 11 проверок восстановления и 19 проверок аудита.
- Shell-синтаксис backend/helper/installer и Bash-синтаксис сборочных скриптов проверены в `tests/run.sh`.
- Браузерная логика выполнена через Node.js с имитацией DOM и XMLHttpRequest. На VPS без Node этот один тест будет явно пропущен; shell/Python-проверки всё равно обязательны.
- Проверена упаковка с тестовыми файлами вместо бинарников: пять файлов аддона, boot_start в S99, синтаксис postinst/prerm. Тестовый пакет не предназначен для установки и не включён в выдачу.
- Реальные iptables, dnsmasq, opkg, OpenVPN/IPsec и перезагрузка роутера локально не испытывались. Работа на вашем роутере после установки пока не подтверждена. I cannot verify this.

## Проверки на роутере после установки

1. Сверить установленную версию через `/opt/bin/opkg status amneziawg`.
2. Apply без изменений: дождаться Completed, проверить свежий статус и LOG.
3. Удалить одну GeoIP-категорию, Apply: выбранный файл и соответствующие статические записи должны исчезнуть, остальные категории сохраниться.
4. Выключить/включить AntiFilter через Apply: проверить таблицу 400, MYAWG, cron; таблица 300 должна оставаться независимой.
5. Проверить трафик с LAN, OpenVPN и IPsec, затем перезагрузить роутер и повторить проверки.
6. Проверку восстановления через намеренную порчу firewall/ipset проводить только при доступном запасном способе управления роутером. Эти разрушительные команды в патч не включены.

Основные исходники для самостоятельной проверки: `addon/amneziawg.sh`, `addon/awg-runtime.sh`, `addon/awg-common.sh`, `addon/awg-ipset-update.sh`, `addon/amneziawg_page.asp`, `tests/test_audit.py`, `tests/test_recovery.py`.
