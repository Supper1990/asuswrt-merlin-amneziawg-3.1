# AmneziaWG for Asuswrt-Merlin

[[Русский]](README.md) · [[English]](README_EN.md)

Клиент **AmneziaWG** с веб-интерфейсом для роутеров ASUS на прошивке **Asuswrt-Merlin**.

Проект предоставляет userspace-реализацию AmneziaWG с поддержкой импорта конфигураций, маршрутизации по устройствам, GeoIP/GeoSite и пользовательских правил.

## Возможности

- **AmneziaWG 2.x и 3.1** — поддержка актуальных конфигураций AmneziaWG
- **Userspace-реализация** — на базе `amneziawg-go`, без необходимости установки отдельного kernel module
- **Веб-интерфейс** — управление AmneziaWG непосредственно из интерфейса Asuswrt-Merlin
- **Импорт конфигурации** — загрузка готового `.conf`
- **Маршрутизация по устройствам** — отдельные правила для устройств локальной сети
- **Полная маршрутизация** — весь трафик выбранного устройства через AmneziaWG
- **Выборочная маршрутизация** — направление через AmneziaWG только выбранного трафика
- **Прямое подключение** — возможность исключить устройство из маршрутизации через AmneziaWG
- **GeoIP** — маршрутизация по IP-адресам и CIDR-подсетям
- **GeoSite** — маршрутизация по доменным спискам
- **Custom Domains** — собственные доменные правила
- **Custom IPs** — собственные IP-адреса и CIDR-подсети
- **DNS-маршрутизация** — интеграция с `dnsmasq` и `ipset`
- **MSS clamping**
- **Обновление GeoIP/GeoSite-списков**
- **Автоматическая проверка обновлений AmneziaWG**
- **Установка обновлений из веб-интерфейса**
- **Сохранение пользовательских настроек и конфигурации при штатном обновлении**
- **Два независимых списка маршрутизации** — веб-интерфейс использует `awg_dst`/таблицу 300, а список AntiFilter — `MYAWG`/таблицу 400
- **Самовосстановление маршрутов** — watchdog восстанавливает таблицу 400 после пересоздания `awg0`, список AntiFilter обновляется ежедневно по cron
- **Поддержка входящих VPN-клиентов** — NAT по метке маршрутизации работает для OpenVPN, IPsec и других VPN-серверных интерфейсов
- **Защита обратного маршрута** — watchdog поддерживает loose `rp_filter` для `awg0` и входящих VPN-интерфейсов
- **Контроль firewall** — watchdog проверяет основные правила, NAT и таблицу 300 и пересобирает их только при обнаружении потери
- **Контроль ipset** — watchdog восстанавливает `awg_dst` при исчезновении или падении числа статических записей ниже безопасного порога
- **Управление AntiFilter** — включение, отключение и ручное обновление отдельного списка доступны в веб-интерфейсе; по умолчанию он включён

## Требования

- совместимый роутер ASUS
- прошивка Asuswrt-Merlin
- установленный Entware
- SSH-доступ к роутеру
- готовая конфигурация AmneziaWG

## Установка

### Поддерживаемые архитектуры

Пакеты `.ipk` доступны для двух архитектур:

- **ARM64 / AArch64** — `aarch64` / Entware `aarch64-3.10`
- **ARMv7 (32-bit ARM)** — `armv7l` / Entware `armv7-3.2`

Проверить архитектуру:

```sh
uname -m
/opt/bin/opkg print-architecture
```

Автоматический установщик определяет архитектуру и выбирает соответствующий пакет.

### Проверенные модели роутеров

Аддон успешно протестирован на следующих устройствах:

| Модель | Архитектура | Entware |
|---|---|---|
| ASUS RT-AX88U Pro | ARM64 / AArch64 | `aarch64-3.10` |
| ASUS RT-AX82U | ARMv7 (32-bit ARM) | `armv7-3.2` |

Список содержит устройства, на которых аддон был протестирован на практике. Другие роутеры с Asuswrt-Merlin и совместимой архитектурой Entware также могут работать, даже если они не указаны в таблице.

### Автоматическая установка с GitHub

Подключитесь к роутеру по SSH и выполните:

```sh
curl -fsSL https://raw.githubusercontent.com/Supper1990/asuswrt-merlin-amneziawg-3.1/main/install-online.sh -o /tmp/install-amneziawg.sh
sh /tmp/install-amneziawg.sh
```

Установщик проверяет архитектуру, скачивает последний `.ipk` из **GitHub Releases**, сверяет его с опубликованным `SHA256SUMS` и устанавливает через Entware.

### Ручная установка

Скачайте `.ipk` пакет из раздела **Releases**.

Используйте пакет с суффиксом `_aarch64-3.10.ipk` для ARM64 или `_armv7-3.2.ipk` для ARMv7.

#### 1. Скопируйте пакет на роутер

```sh
scp amneziawg_*.ipk admin@<IP-РОУТЕРА>:/tmp/
```

#### 2. Подключитесь к роутеру по SSH

```sh
ssh admin@<IP-РОУТЕРА>
```

#### 3. Установите пакет

```sh
/opt/bin/opkg install /tmp/amneziawg_*.ipk
```

### После установки откройте веб-интерфейс

После установки:

1. Выйдите и снова войдите в веб-интерфейс Asuswrt-Merlin.
2. Откройте страницу **AmneziaWG**.
3. Импортируйте конфигурацию `.conf`.
4. Проверьте импортированные параметры.
5. Нажмите **Apply**.
6. Запустите AmneziaWG.
7. При необходимости настройте правила маршрутизации для устройств.

## Маршрутизация

Для каждого устройства локальной сети можно определить собственный режим работы.

### Весь трафик

Весь трафик выбранного устройства направляется через AmneziaWG.

### Выборочная маршрутизация

Через AmneziaWG направляется только трафик, соответствующий выбранным GeoIP, GeoSite и пользовательским правилам.

### Прямое подключение

Трафик выбранного устройства направляется напрямую.

### Дополнительный список AntiFilter

Пакет отдельно поддерживает список `https://antifilter.download/list/allyouneed.lst`:

- `awg_dst`, метка `0x100` и таблица 300 управляются веб-интерфейсом;
- `MYAWG`, метка `0x66` и таблица 400 управляются скриптом `awg-ipset-update.sh`;
- переключатель **Enable AntiFilter** в веб-интерфейсе включает или полностью отключает его правила, NAT, таблицу 400 и задание cron;
- по умолчанию AntiFilter включён;
- watchdog каждые 5 минут восстанавливает правила, таблицу 400 и опустевший `MYAWG` из локального кэша;
- при включённом AntiFilter список обновляется ежедневно в 04:10;
- кнопка **Update AntiFilter Now** запускает обновление вручную.
- включение, отключение, результат обновления и ошибки AntiFilter отображаются в блоке **Log**.

Запустить обновление вручную:

```sh
/jffs/addons/amneziawg/amneziawg.sh update_ipset
```

## GeoIP

GeoIP позволяет задавать маршрутизацию по IP-адресам и CIDR-подсетям.

Можно использовать готовые списки, а также добавлять собственные адреса и сети через **Custom IPs**.
В `awg_dst` загружаются только GeoIP-категории, выбранные в поле **GeoIP Service Lists**. После нажатия **Apply** снятые категории удаляются без дополнительного обновления списков; результат удаления записывается в журнал. GeoSite-категории разбираются из актуального формата `dlc.dat_plain.yml`, а очищенные GeoSite и Custom Domains больше не оставляют старых правил.

После применения настроек предварительное DNS-разрешение GeoSite-доменов выполняется в фоне. Веб-интерфейс не ожидает завершения всех DNS-запросов; начало и окончание заполнения `awg_dst` отображаются в журнале.

Пример:

```text
8.8.8.8
1.1.1.0/24
```

## GeoSite

GeoSite позволяет задавать маршрутизацию по доменным спискам.

Для обработки доменных правил используется интеграция с `dnsmasq` и `ipset`.

Для корректной работы доменной маршрутизации клиентские устройства должны использовать DNS-сервер роутера.

## Custom Domains

В **Custom Domains** можно добавить собственные доменные имена.

Пример:

```text
example.com
example.org
```

## Custom IPs

В **Custom IPs** можно добавить отдельные IP-адреса или CIDR-подсети.

Пример:

```text
8.8.8.8
1.1.1.0/24
```

## Обновление

AmneziaWG автоматически проверяет наличие новой версии.

Если доступно обновление, информация о нём отображается в веб-интерфейсе.

Обновление можно установить непосредственно из веб-интерфейса AmneziaWG.

При штатном обновлении пользовательские настройки и конфигурация сохраняются.

## Управление через SSH

### Запуск

```sh
/opt/etc/init.d/S99amneziawg start
```

### Остановка

```sh
/opt/etc/init.d/S99amneziawg stop
```

### Перезапуск

```sh
/opt/etc/init.d/S99amneziawg restart
```

### Состояние AmneziaWG

```sh
awg show
```

## Удаление

Для удаления AmneziaWG:

```sh
/jffs/addons/amneziawg/amneziawg.sh uninstall
opkg remove amneziawg
```

### Исправления восстановления в 2.2.0-17

- Watchdog сохраняет задание cron после неудачного восстановления; перед перезапуском проверяет два адреса до трёх раз. Устаревшие блокировки снимаются с проверкой PID.
- Apply, запуск и обработчики firewall выполняются последовательно. Изменение параметров туннеля через Apply вызывает перезапуск; изменение только маршрутизации — пересборку правил.
- Watchdog сверяет сохранённые правила цепочки AWG и DNS-перехвата, включая правила устройств.
- Явная политика устройства Direct обходит AntiFilter через метку 0x101 и правило приоритета 9 в main. Индивидуальная Geo-политика не перекрывается общей политикой полного туннеля. Таблицы 300 и 400 сохранены.
- AntiFilter сериализует обновление, восстановление и отключение, проверяет переключатель перед активацией. Изменённый список заменяется через временный ipset и swap; кеш и хеш не фиксируются при ошибке загрузки ipset. Инкрементальное обновление заменено полной подготовкой изменённого списка. Неизменённый исправный набор не пересоздаётся.
- Неудачное обновление Geo не меняет время последнего успешного обновления.

Ограничение: аддон управляет IPv4; прямой выход через WAN по IPv6 не блокируется. При включённом IPv6 журнал предупреждает об этом. Проверка наличия правил не гарантирует отсутствие конфликтующих правил других аддонов.

Проверки без роутера: `python3 tests/test_recovery.py` (имитация системных команд; не заменяет проверку на Merlin).

### Исправления 2.2.0-18

Проверка списков до применения, восстановление при ошибках, полный контроль состава AntiFilter, квитанции операций в интерфейсе, живой статус, сохранение MAC, единый автозапуск и обновление пакета с проверенным пакетом отката. Поле DNS применяется к выбранным доменам. Общая таблица соединений больше не очищается.

Проверки, ограничения GeoSite/IPv6 и порядок приёмки: [docs/AUDIT-18.md](docs/AUDIT-18.md). Перед упаковкой выполняется `bash tests/run.sh` (Python 3; браузерный тест дополнительно использует Node.js). Побитовая воспроизводимость Docker-сборки не гарантируется.

### Исправление запуска 2.2.0-19

На роутере при старте 2.2.0-18 зафиксировано `command: not found` из обёртки firewall. Теперь `ip` и `iptables` предварительно находятся в PATH и запускаются по абсолютному пути. Проверка обязательных ошибок сохранена; добавлены сообщения о сбое команды и тесты оболочки без `command`.

### Восстановление вкладки после загрузки: 2.2.0-20

Регистрация вкладки отделена от запуска туннеля и использует свою блокировку. `mount_ui` не запускает AmneziaWG. Сценарий S99 параллельно запускает восстановление страницы, затем выполняет `boot_start` с учётом настройки автозапуска. Существующий `services-start` также может вызывать `mount_ui`: повторный вызов переиспользует страницу.

При поздней готовности веб-интерфейса выполняются до 12 попыток с паузой 5 секунд. Задание `awg_ui_watchdog` раз в минуту проверяет страницу и запись меню, в том числе при остановленном туннеле. Оно удаляется при удалении аддона. Рабочая страница не удаляется перед регистрацией новой; отсутствие ожидаемого пункта меню вызывает ошибку без перезаписи текущего меню.

Проверки: 40 тестовых методов в `bash tests/run.sh`, включая 7 проверок UI с имитацией файлов и mount. Реальную загрузку Merlin и взаимодействие с другими аддонами нужно проверить после установки. Ручное восстановление вкладки на роутере подтверждено пользователем, но причина первоначального сбоя по журналу не установлена; конкуренция запуска и регистрации — обнаруженный в коде риск, устранённый этой версией.

### Остановка DNS-заполнения при Apply: 2.2.0-21

Apply запрашивает остановку фонового DNS-worker. Worker проверяет запрос во время ожидания DNS, завершает свой дочерний `nslookup` и освобождает блокировку после `wait`. Бюджет ожидания запроса — восемь секунд: 80 интервалов по 0,1 секунды, либо восемь по секунде, если дробный sleep недоступен. Если остановку подтвердить нельзя, применение по-прежнему откладывается. Процесс в состоянии zombie не считается активным. При обновлении старый worker сохраняет прежний путь остановки до первого запуска новой версии.

Проверки: отмена активного запроса, повторный запуск, завершение и тайм-аут запросов, чужой PID, разбор состояния процесса и запуск без задания. Проверки процессов выполняются с имитацией `/proc`; необходима проверка Apply на роутере.
